# Sprint After Nine｜九點以後：首版設計規格

日期：2026-10-21

狀態：對話設計已採用；本書面規格待使用者審閱。

平台：桌機瀏覽器優先、支援行動觸控、GitHub Pages 靜態託管。

## 1. 目的與成功標準

製作一款以軟體工程師工作日為題材的 3D 辦公室探索、職場決策與時間管理遊戲。玩家體驗需求不確定、會議與交付壓力之間的取捨，而非只靠快速點擊累積分數。

一局目標體驗時間約 10–15 分鐘，模擬 09:00–18:00。實際遊玩時間隨閱讀速度不同；沒有強制現實時間倒數。至少可用三種職級完成一個完整工作日，取得可解釋的結算。

本任務的技術限制優先於上層電商專案預設：不使用 Angular、後端、資料庫或金流。

## 2. 已採用方向與範圍

- 英文名稱：Sprint After Nine。
- 中文名稱：九點以後。
- 主要呈現：three.js 低多邊形辦公室，搭配 HTML 工作日誌與決策介面。
- 選角：Junior、Senior、管理階層。
- 任務分支：前端、後端、全端；管理階層選擇團隊方向，影響情境內容。
- 首版不含多人連線、帳號、雲端存檔、真實 Figma／GitHub 工作資料串接或付費功能。
- 「成語填空」依已採用提案視為誤植，不加入成語題目。
- 參考職業模擬遊戲的探索與情境選擇模式，不複製其程式碼、圖片或劇情。

## 3. 工作日與核心循環

首頁 → 選職級與方向 → 簡短操作教學 → 探索辦公室 → 選擇任務／處理事件 → 下班結算 → 重玩或返回首頁。

時間採行動推進制：走路、閱讀與開啟選單不消耗遊戲時間；確認任務選項後消耗 15、30 或 45 分鐘。介面在確認前顯示成本和預期影響。跨越 18:00 的行動不允許開始；仍可選擇提前下班，按目前成果結算。

固定排程：

| 時間 | 活動 | 時長 | 影響 |
|---|---|---|---|
| 09:30 | Sprint 站會 | 15 分鐘 | 回報進度、揭露阻礙 |
| 11:00 | 需求會議 | 30 分鐘 | 澄清驗收條件或承擔返工風險 |
| 15:00 | 教育訓練 | 30 分鐘 | 提升品質或保留交付時間 |

行動若跨過尚未處理的會議開始時間，先顯示衝突提示，提供取消行動或明確略過會議的選擇。準時到達會議時間則顯示參加／略過選項。每場會議只能處理一次，不得重複扣分或發放獎勵。

其他時間可選擇開發、測試、審查、需求澄清、支援同事或休息。12:00 後提供一次午休選項；短暫休息可重複執行但會消耗時間。

## 4. 角色與任務

每種角色有至少四項具前後依賴的主要任務，共用事件系統，但選項、成本與效果不同。

| 角色 | 主要工作鏈 | 特色取捨 |
|---|---|---|
| Junior | 閱讀 SA 規格 → 依設計稿開發 → 補測試 → 修正審查問題 | 求助消耗時間，但降低返工；猜測規格較快但增加風險 |
| Senior | 澄清規格 → 整合實作 → 程式碼審查與指導 → 發布準備 | 親自處理與協助團隊之間取捨 |
| 管理階層 | 排定優先級 → 協商範圍 → 排除阻礙 → 確認交付 | 承諾更多範圍會增加進度壓力，不能靠會議無限得分 |

前端情境包含設計稿斷點、互動狀態與無障礙；後端包含 API 契約、驗證與錯誤處理；全端包含契約整合與跨層排查。設計稿以遊戲內虛構規格卡呈現，不要求外部帳號。

事件池至少包含：臨時需求、測試退件、合併衝突、正式環境事故、同事求助、SA 規格缺漏。每局依可重現的亂數種子安排三次事件，避免同一事件重複出現。事件只在行動結束後出現，不打斷玩家正在閱讀的對話。

事件選擇是具成本的情境解題，不執行玩家輸入的程式碼。已完成的主要任務與一次性獎勵不能重複領取。

## 5. 資源與結局規則

四個主要指標均限制在 0–100：

- 交付進度：完成主要任務增加；單純休息與略過會議不增加。
- 程式碼品質：測試、澄清與審查改善；走捷徑與未處理事故降低。
- 團隊信任：清楚溝通、協作與履行承諾改善；失約及隱瞞問題降低。
- 精力：高負荷行動降低，休息恢復。

起始值：進度 0、品質 65、信任 60、精力 85。角色差異由任務效果與成本實現，避免僅以不同起始數值假裝差異。

精力歸零時停止工作並結算。其他情況在 18:00 或玩家提前下班時結算。結局依以下順序判定，保證只產生一種主要結局：

1. 精力為 0：過勞收場。
2. 進度 ≥ 80、品質 ≥ 65、信任 ≥ 50：穩定交付。
3. 進度 ≥ 80、品質 < 65：技術債留到明天。
4. 進度 ≥ 80、品質 ≥ 65、信任 < 50：交付完成，合作失溫。
5. 進度 < 80、信任 ≥ 65：誠實協商，明天再戰。
6. 其餘：帶著未完清單下班。

結算列出主要指標、完成與未完成任務、關鍵選擇及其影響。不得把遊戲分數描述為真實工作能力評量。

## 6. 場景、操作與無障礙

場景包含辦公桌、會議室、協作白板、測試區及茶水間；固定等角鏡頭，保留清楚的走道與互動標記。

- 桌機：WASD／方向鍵移動，E 互動；點擊站點也可前往。
- 行動：點擊站點或畫面方向按鈕；所有決策使用原生按鈕。
- 共同：HTML 站點清單提供直接選擇功能，不必精準操作 3D 角色。
- Esc 關閉非必要面板或開啟暫停；對話開啟時不讓角色持續移動。
- 鍵盤焦點可見；面板關閉後回復原觸發按鈕焦點；不設鍵盤陷阱。
- 重要資訊同時用文字與圖示表達，不只依賴色彩。
- 觸控目標至少 44 × 44 CSS 像素，支援減少動態效果偏好。
- WebGL 不可用時顯示明確說明，HTML 站點清單仍可完成遊戲。
- 聲音預設關閉，由使用者手動開啟；不依賴聲音傳遞必要資訊。

驗證尺寸為 390 × 844、768 × 1024、1440 × 900。行動橫向時介面可捲動，不裁切必要按鈕。

## 7. 視覺與內容

採「低多邊形辦公室 × 紙本工作日誌」。暖白背景 #F2EDE3、墨色文字 #25332D、森林綠 #385747、木色 #B98C62、磚紅 #AD5142；實作時驗證文字對比，不以色票名稱代替檢查。

字體優先使用系統繁體中文無襯線字體，數字及時間採等寬字體。版面透過紙張邊線、印章、便條與局部不對稱形成辨識度，不使用滿版漸層、霓虹光暈或大量玻璃效果。

角色與家具為原創簡化幾何。動畫只用於移動、互動提示及結果回饋，減少動態效果模式關閉裝飾性動畫。文字使用臺灣繁體中文，幽默針對工作情境，不羞辱職級或特定群體。

## 8. 技術與模組責任

- HTML／CSS／Vanilla JavaScript／原生 ES Modules；three.js 為唯一必要的遊戲繪圖函式庫。
- 發布產物自含 three.js 與必要資產，以相對路徑載入，支援 GitHub Pages 專案子路徑。
- Node.js 僅用於本機測試與靜態服務；部署後沒有後端服務。
- Blender 為選用資產製作工具。首版使用可直接以 three.js 建立的幾何模型，不以 Blender 安裝作為執行前提。目前命令搜尋未找到 Blender，不宣稱已產出或驗證 .blend 資產。
- Unreal Engine 與本案禁止大型遊戲引擎的限制衝突，依已採用提案排除。

建議模組：

| 模組 | 責任 |
|---|---|
| game-state.js | 純函式狀態轉移、時間、資源、排程、結局 |
| content.js | 角色、任務、事件及中文文案資料 |
| scene.js | three.js 場景、移動、互動位置、尺寸調整 |
| ui.js | DOM 面板、可存取操作、狀態呈現 |
| storage.js | 存檔格式驗證、版本與例外處理 |
| audio.js | 使用者啟用後的簡短 Web Audio 音效 |
| main.js | 初始化與模組協調 |

場景不能直接修改分數，所有操作經狀態核心檢查後提交，介面與場景再讀取同一份狀態。

## 9. 儲存、錯誤處理與安全

使用 localStorage 自動儲存每次已確認行動的狀態、選角、亂數狀態及已處理事件。位置可重設為安全起點，不必逐幀儲存。待回覆事件也需保存，重新整理不能跳過代價。

存檔包含版本，讀取時檢查欄位、數值範圍、合法任務與事件識別碼。損壞或不相容時提供開始新局，不使遊戲無法開啟。儲存被停用或容量不足時以記憶體繼續並顯示提示。

暫停、分頁失焦與結算狀態不接受背景移動或重複任務操作。雙擊選項不得重複推進時間。

不蒐集個人資料，不要求真實姓名，不載入追蹤服務。不讀取、輸出、提交或推送憑證、token、.env 或私人金鑰。Git 操作以明確檔案清單加入版本控制；認證使用既有工具的登入狀態。

## 11. 里程碑與風險控制

1. 設計規格審閱：檢查完整性、一致性及可驗收性，建立規格提交。
2. 實作計畫：依 writing-plans 建立工作順序與各階段驗證，再由使用者審閱。
3. 遊戲核心：先驗證規則與任務資料，再接上介面。
4. 可玩場景：驗證 3D 與 HTML 替代操作。
5. 完整首版：驗證三職級、事件、結算、儲存及視覺。
6. 審查與交付：執行 requesting-code-review、修正問題，再依 finishing-a-development-branch 完成 Git 與部署。

主要風險與處理：

- 範圍膨脹：共用系統及分支文案，不製作九套獨立遊戲。
- 行動裝置效能：限制幾何數、陰影與像素比例，必要時降級。
- 遊戲平衡：用固定種子測試各角色可達成成功結局；不保證所有任意選擇都能成功。
- 會議與任務衝突：確認前提示，不默默跳過排程。
- Pages 子路徑：相對資產路徑，部署後重新驗證載入。
- GitHub 權限未知：尚未指定或建立遠端，不承諾未取得的部署權限。

推送前必須顯示確定的 remote、branch 與 commit。使用者已要求推送與 Pages 部署；可用權限足夠時照指示執行，不另設一般性發布確認。
